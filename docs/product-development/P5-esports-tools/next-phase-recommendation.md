# Next Phase Recommendation (P5 → P6)

**Recommended: second tool via the extension process (roster/slot builder
candidate) — but only after a privacy review.**

Rationale: the architecture is proven by one tool; a second, different-
shaped tool (paste-and-normalize rather than calculate) is the cheapest way
to validate that the extension process holds without modifying existing
tools. The roster concept already carries an ADAPT marking for its pure
services, but pasted registrations are personal data — scope, retention
(none), and abuse handling must be decided first.

**Do not** start monetization, accounts, history, or share links as part of
P6: those are identity/persistence decisions that cut across pillars and
belong with the platform-wide organization/identity work, not inside Tools.

**Also deferred to owner input:** the homepage-pillar threshold question
(§2 of `deferred-decisions.md`) and any indexing change.
